# The Sapper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Sapper, a hidden melee demolitions class with a sledgehammer, landmines joined by tripwires and a cave-in that crushes a pack and walls off a tunnel, unlocked at its plaque.

**Architecture:** Rubble is only ever a change to the walkable field: `fieldFns` gains rock capsules that it writes into `F` and takes out again from a base copy, so collision, sight, routes, the camera and `ceilAt` all follow with no special cases. The class is a `CLASSES` entry with hammer `MOVES`, a `mine` tool (`G.mines`), a `cavein` ability (`G.caveins`) and a Sapper branch in the execution. The plaque goes live through the existing code machinery.

**Tech Stack:** Vanilla JS in the concatenated `src/*.js` scope, own WebGL renderer, headless Chromium tests through `test.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-18-sapper-design.md`. Read it and `CLAUDE.md` before any task.

## Global Constraints

- Declare every name once across all of `src/`; `grep -n "name" src/*.js` before adding one.
- `node build.mjs` after every source change. Tests run against `dist/index.html`.
- No dependencies, no assets, no textures. Rocks are drawn from renderer primitives.
- Rubble is only ever a change to the field. No reader of the field (`fieldAt`, `resolve`, `los`, `route`, `ceilAt`, the camera, projectiles) gets a rubble check of its own.
- No body ends a cave-in inside rock, except the training dummy, which stays pinned.
- The Sapper's own blasts never call `hurtPlayer`.
- No new touch or pad buttons, no change to `touchLayout`.
- A plain code never appears in a committed file, commit message, test or comment. Only the hash goes in `SHIPPED_CODES`; the plain code goes in the ignored `tests/codes.local.json` and to the owner in conversation.
- In the game the class is "Sapper". Nothing named after the film the owner mentioned.
- `G.world` from `genWorld` and from `genHub` keep the same fields.
- Commit messages carry no `Co-Authored-By` or `Claude-Session` trailers.
- Test steps return `{ pass, ... }`; anything but `pass: true` fails the run.

## Review Focus

1. **A cave-in thrown at a wall point-blank, or landing at the Sapper's feet.** Expected: the Sapper is pushed to its own side, out of the rock, and takes no damage. Test in Task 3.
2. **Rubble standing when the world changes or the player respawns in the same cave** (`respawn`, `enterHub`, `enterCave`, `toBase`). Expected: every rock is taken out of the field, so the cave the player respawns in has no invisible wall. Test in Task 3.
3. **An enemy walking a route through the spot where rubble rises.** Expected: its route is dropped, it never stands inside rock (`fieldAt(e) >= 0` every step), and it goes round or searches. Test in Task 3.
4. **Two cave-ins that overlap, one crumbling first.** Expected: the field under the second stays rock until it crumbles. Test in Task 1 (field) and Task 3 (in play).
5. **Mines in the hall, where tools refill on their own.** Expected: never more than `MINE.cap` live mines; the oldest goes quiet. The player never sets off a mine. Test in Task 4.

### Task 1: Rock in the field

**Files:**
- Modify: `src/03_world.js` (`fieldFns` at line 14, `genWorld`'s return at line 820), `src/03b_hub.js` (`genHub`'s use of `fieldFns` at line 121 and its return)
- Test: `tests/t20.mjs` (new)

**Interfaces:**
- Produces, from `fieldFns(F, minX, minZ, W, H)` and on every `G.world`:
  - `addRock(ax, az, bx, bz, r) -> id` (integer): a capsule from `(ax, az)` to `(bx, bz)` with radius `r`.
  - `removeRock(id) -> void`; unknown ids do nothing.
  - `clearRocks() -> void`: takes every rock out.
- Behaviour: grid point `(i, j)` is world point `(minX + i, minZ + j)`, index `j * (W + 1) + i`. On the first `addRock`, `fieldFns` keeps `base = Float32Array.from(F)`. A rock patches every grid point within its capsule's bounding box grown by `ROCK_PAD = 3`, setting `F[k] = min(base[k], dist(point, segment) - r)` over every live rock that covers that point. `removeRock` and `clearRocks` recompute the points they covered from `base` and the rocks still live. `F` is changed in place, so `route`, which reads `F` directly, follows.

### Task 3: The cave-in

**Files:**
- Modify: `src/06_game.js` (`stagger` at line 1592, `useSpecial`, `update` after `bombsUpdate`, `resetRun` at line 1308, `respawn` at line 1426), `src/07_render.js`, `src/04_audio.js`, `src/09_main.js` (`DF`)
- Test: `tests/t20.mjs`

**Interfaces:**
- Consumes: `world.addRock`, `removeRock`, `clearRocks` (Task 1); `CLASSES.sapper.special.id === "cavein"` (Task 2).
- Produces:
  - `stagger(e, k = 1)`: as today, with `e.dur` multiplied by `k`.
  - `CAVEIN = { fuse: 0.9, range: 12, thick: 1, half: 5.5, into: 0.8, dmg: 55, post: 60, life: 12, crumble: 1.5, stag: { brute: 0.75 } }`.
  - `G.caveins`: entries `{ x, z, yaw, t, phase, ax, az, bx, bz, id }`. `phase` runs `"fuse"` (charge in the air and on the ground, `t` counting down from `CAVEIN.fuse`), then `"stand"` (`t` counting down from `CAVEIN.life`), and the entry goes when `t` reaches 0 in `"stand"`.
  - `startCaveIn(tx, tz) -> void` lands a cave-in at a point (the ability calls it; tests call it through `DF`).
  - `caveUpdate(dt)` called from `update` right after `bombsUpdate`.
  - `DF.startCaveIn`, `DF.CAVEIN`, `DF.stagger`.

Behaviour:
- **Aim.** Locked: the lock target's position. Not locked: along `cam.yaw` to 9 m. Either way, clamped to `CAVEIN.range` and pulled back along the line to the last point with `fieldAt > 0.3`. `p.yaw` turns to it, `p.throwT = 0.4`, focus is spent, `SFX.whoosh(true)`.
- **The ridge.** At the end of the fuse, the capsule lies across the throw direction (perpendicular to `yaw`) through `(x, z)`. Each end is found by stepping 0.25 m outward until `fieldAt < 0.3` or `CAVEIN.half`, then going `CAVEIN.into` further, so a ridge in a tunnel runs into both walls. Radius `CAVEIN.thick`.
- **Impact, in this order:**
  1. Every live enemy whose body touches the capsule grown by 0.4 takes `hitEnemy(e, dmg, post, { src: "aoe", heavy: true, fx: x, fz: z })`. Then, if it is alive and not the boss, `stagger(e, CAVEIN.stag[e.type] || 1)`.
  2. Live mines within `thick + 0.5` of the segment go off (Task 4 adds mines; until then there are none).
  3. `addRock` with the ridge.
  4. Every body inside the capsule grown by its own radius, the player and live enemies but not the dummy, is moved along the ridge's normal to `thick + r + 0.15` from the segment, on the side it is on. A body within 0.05 of the line goes to the side the player is on, and the player in that case to the side it threw from. Then `resolve`.
  5. Every enemy's `route` is set to `null`.
  6. `G.shake = 1`, `SFX.rumble()`.
- **Crumble.** When `"stand"` reaches 0: `removeRock(id)`, every enemy's `route` to `null`, `SFX.crumble()`, a burst of dust sparks.
- **Clean up.** `resetRun` and `respawn` call `G.world.clearRocks()` (if the world has one) before anything else and set `G.caveins = []`.
- **Drawing.** The charge flies in an arc during the first 0.4 s of the fuse and blinks in `HAZARD` on the ground. The rocks fall from `ceilAt` over the last 0.3 s of the fuse. While standing, the ridge is a heap of faceted rock primitives filling the capsule, seeded from the entry so it does not flicker. In the last `CAVEIN.crumble` seconds the heap shakes and sheds dust.
- **Sounds.** `SFX.rumble()` (a long low roar) and `SFX.crumble()` (a rattle of small stones).
