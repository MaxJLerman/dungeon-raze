# Dev menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local-only dev menu that unlocks the hidden classes, enters any gate, jumps to either boss and toggles god mode.

**Architecture:** Dev code lives in `src/dev/`, which `build.mjs` appends after `src/*.js` unless `--release` is passed; the Pages workflow builds with `--release`. Core code declares `let DEV = null` and reads it at four seams (`classOpen`, `hurtPlayer`, `grabPlayer`, `update`); the dev file sets `DEV` only when `devHost(location)` passes. The dev screen's DOM is built by the dev file, so the template and the release page carry nothing of it.

**Tech Stack:** Plain JS concatenated into one function scope (no imports), Node build script, Playwright tests through `test.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-23-dev-menu-design.md`

## Global Constraints

- Every `src/**/*.js` file shares one scope: declare each name once across `src/` and `src/dev/`. No imports or exports.
- `node build.mjs` after every source change; `dist/index.html` is what runs and is not committed.
- The release build (`node build.mjs --release`) must contain no dev code: no `devHost`, no `scr-dev`, no `src/dev/` text. Only the `let DEV = null` line and the four `DEV &&` checks may remain.
- The menu turns on only for `location.protocol === "file:"` or hostname `localhost`, `127.0.0.1` or `[::1]`.
- Dev actions never write to the save: dev unlocks live in `DEV.unlocked`, never in `UNLOCKED`; no dev action calls `clearGrade`.
- God mode is off on every page load.
- Commit messages carry no `Co-Authored-By` or `Claude-Session` trailers.
- Do not reintroduce the shadow-necromancer class; do not add network requests.

## Review Focus

1. Backquote bound to a game action by the player: in play the key must do that action and not open the menu (Task 2 test "backquote yields to a binding").
2. Backquote while the Controls screen waits for a key to bind: it must bind, not open the menu (Task 2 test "backquote is ignored outside title, pause, play and dev").
3. A dev-unlocked class chosen and then saved: the next load must fall back to the first pickable class, not keep a locked class (Task 3 test "a dev class does not survive a reload").
4. God mode across world swaps and in a real boss fight: it must stay on through `enterCave`, `enterHub` and `respawn`, and the player must take nothing from every source, including damage over time and the crocodile's falling ceiling (Task 5 test "god holds through a crocodile fight").
5. A cave whose path is too short for a rest point before the boss (`shrines.length === 1`): the boss jump must still work, starting at the arrival rest point (Task 4 test "boss jump lands at the last rest point", seeds 1 to 12).
