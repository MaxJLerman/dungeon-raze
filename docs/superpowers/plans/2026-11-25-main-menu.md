# Main menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first page is a main menu (Play solo, Play online, How to play, Controls) with no class picker; the class is chosen after a Play button; the pause, death and win screens can exit to the main menu.

**Architecture:** The `title` state stays and becomes the main menu. The existing `class` screen gains a forward button (`#btnPlay`) when it is opened from the main menu, for a solo or an online start. One new function, `toTitle()`, is `enterHub()` then `show("title")`. `?coop=1` is no longer read.

**Tech Stack:** Plain JavaScript in `src/`, one HTML template, `node build.mjs`, Playwright tests through `test.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-25-main-menu-design.md`

## Global Constraints

- `node build.mjs` after every source change; the page that runs is `dist/index.html`.
- All `src/*.js` share one function scope: declare a name once across `src/`. Nothing outside `src/dev/` names anything declared there.
- Button text, exact: "Play solo", "Play online", "How to play", "Controls", "Enter the hall", "Continue", "Exit to main menu", "Return to base".
- Ids, exact: `#btnSolo`, `#btnCoop`, `#btnPlay` (now on `#scr-class`), `#classSub`, `#btnExit`, `#btnDeadExit`, `#btnWinExit`.
- Room screen heading: "Play online". Its line: "One of you hosts a room and sends the other its code. You play the class you just chose."
- The class screen's line from pause, unchanged: "Switching mid-run keeps your place in the cave and your share of health."
- Pointer lock, fullscreen and audio start only from a click or key handler (`play()` is called from the forward button's click).
- An address with `?coop=1` still loads and behaves as one without it.
- Never read, print or copy any `tests/codes.local.*` file.
- Commits: no `Co-Authored-By` or `Claude-Session` trailers. No em dashes and no ", and" in commit messages.
- A test step fails the run when it returns an object whose `pass` is not `true`. Page test steps that read the DOM after a click wait two animation frames where the HUD is involved.

## Review Focus

1. **A stale forward button.** The class screen opened from the pause screen after a solo or online start must have `#btnPlay` hidden; pressing it mid-run would restart or open a room. (Task 1, t30 "class from pause".)
2. **One pad press, one screen.** A pad press on Play solo opens the class screen and must not also press Enter the hall on the same press. (Task 1, t16.)
3. **The class picked after an exit is the class played.** Exit to main menu, pick another class, Enter the hall: `G.player.clsId` is the new one. (Task 2, t30.)
4. **Exit in the middle of a portal fade.** With `G.trans` set, exit, then Play solo and Enter the hall: two seconds later the zone is still the hall. (Task 2, t30.)
5. **The smallest phone.** On `iphone-se` in landscape the main menu's four buttons are all inside the screen, and on the class screen `#btnPlay` can be reached by scrolling (its bottom is within the screen's `scrollHeight`, and after `scrollIntoView` its box is inside the viewport). (Task 1, t30 on a device.)
